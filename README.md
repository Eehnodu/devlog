# devlog — 코드로 남긴 변천사

2025년 2월 단일 파일 구조의 Django 챗봇에서 2026년 도메인 모듈 구조의 ERP 까지, 같은 성격의 작업을 반복하며 드러난 한계를 하나씩 바꿔 온 과정을 **실제 코드 조각**으로 남긴 저장소입니다.
주제별로 폴더를 나누고, 폴더 안에 단계마다 그 시기의 코드와 "무엇이 문제였고 어떻게 바꿨는지"를 적었습니다.

글로 정리한 전체 흐름은 노션의 [성장 과정](https://oil-football-a51.notion.site/3dc0669f896d816ea3d6ca10a9e131d8) 에 있고, 이 저장소는 그 글의 근거가 되는 코드입니다.

## 읽는 법

- 폴더마다 `README.md` 가 있습니다. 단계별로 **어디서 · 문제 · 바꾼 것 · 결과 · 코드** 순서이고, 마지막에 지금 기준이 무엇인지 적었습니다.
- 단계 폴더(`1-xxx/`, `2-xxx/` …)에는 그 단계를 보여주는 핵심 조각만 있습니다. 실행용이 아니라 읽기용이라 30~150줄로 잘랐고, 잘라낸 곳은 `# ... (생략)` 으로 표시했습니다.
- 파일 맨 위 주석에 어느 프로젝트의 어느 시기 코드인지 적었습니다.
- 회사 프로젝트는 고객사 이름 · 도메인 · 키 · 업무 데이터를 지우고 구조만 남겼습니다. 프로젝트 이름은 서비스 성격을 설명하는 이름으로만 부릅니다. 당시 파일이 서버에만 있어 남지 않은 설정(서비스 유닛 · 웹 서버 설정 등)은 운영 기준대로 다시 적었고, 그 사실을 파일 헤더에 밝혔습니다.
